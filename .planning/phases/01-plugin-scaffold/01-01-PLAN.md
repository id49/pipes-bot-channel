- `"channels": ["pipes-bot"]` — declares this plugin provides the pipes-bot channel
- `"configSchema"` — JSON Schema requiring `apiKey` string with `minLength: 1` and `pattern: "^pk_"`. Set `additionalProperties: false`.
- `"uiHints"` — label "PipesBot API Key", sensitive: true, placeholder "pk_..."

**tsconfig.json:**
- `"compilerOptions"`: strict mode, module "nodenext", moduleResolution "nodenext", target "es2022", skipLibCheck true, noEmit true (type checking only — jiti handles loading)
- `"include": ["index.ts", "src"]`

<task type="auto">
  <name>Task 2: Create plugin entry point and service lifecycle</name>
  <files>index.ts, src/service.ts</files>
  <action>
Create two TypeScript files:

**src/service.ts:**
- Export a function `createPipesBotService` that returns an `OpenClawPluginService` object
- Service has `id: "pipes-bot-channel"`
- `start(ctx)`: Read apiKey from `ctx.config.plugins?.entries?.["pipes-bot-channel"]?.config` cast as `{ apiKey?: string } | undefined`. Validate it exists and starts with `"pk_"`. If invalid, log error via `ctx.logger.error` with message "pipes-bot-channel: invalid or missing pk_ API key -- not starting" and return early. If valid, log info "pipes-bot-channel: service started".
- `stop(ctx)`: Log info "pipes-bot-channel: service stopped". This is a Phase 1 stub — Phase 2 will add WS teardown here.
- Import types from `"openclaw/plugin-sdk"`: `OpenClawPluginService`, `OpenClawPluginServiceContext`

**index.ts:**
- Import `createPipesBotService` from `"./src/service.js"` (note: `.js` extension for ESM resolution with nodenext)
- Import `OpenClawPluginApi` type and `emptyPluginConfigSchema` from `"openclaw/plugin-sdk"`
- Create `const plugin` object with:
  - `id: "pipes-bot-channel"`
  - `name: "PipesBot Channel"`
  - `description: "WhatsApp channel via PipesBot managed proxy"`
  - `configSchema: emptyPluginConfigSchema()` — Phase 1 uses empty schema in the export; the manifest handles real validation. Research Pitfall 3 notes both must eventually align, but for Phase 1 this is correct per the diagnostics-otel pattern.
  - `register(api)` — synchronous (NOT async, per research Pitfall 2). Calls `api.registerService(createPipesBotService())`. Logs "pipes-bot-channel: registered" via `api.logger.info`.
- `export default plugin`
  </action>
  <verify>
Run: `npx tsc --noEmit` (install deps first with `npm install`) — should pass with no errors.
If openclaw types are not resolvable (it is a dev dep that may not install without a registry), verify by: reading both files and confirming all import paths are correct, the register function is synchronous, and the service has start/stop methods.
  </verify>
  <done>
index.ts default-exports a plugin object with id, name, description, configSchema, and synchronous register that calls api.registerService. src/service.ts exports createPipesBotService returning a service with start (validates pk_ key) and stop (logs shutdown). No async register, no resource leaks possible in Phase 1 stub.
  </done>
