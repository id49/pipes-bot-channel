**Create `src/status-store.ts`:**

A simple module-level state store for connection health. Three exports:

1. **`PipesBotConnectionStatus` type:**
   ```typescript
   export type PipesBotConnectionStatus = {
     connected: boolean;
     authFailed: boolean;
     lastConnectedAt: number | null;
     lastError: string | null;
   };
   ```

2. **Module-level state:** `let _status: PipesBotConnectionStatus` initialized to `{ connected: false, authFailed: false, lastConnectedAt: null, lastError: null }`.

3. **`updateConnectionStatus(patch: Partial<PipesBotConnectionStatus>): void`** — Merges patch into `_status` via spread.

4. **`getConnectionStatus(): PipesBotConnectionStatus`** — Returns a shallow copy of `_status` (spread to prevent mutation).

**Create `src/channel.ts`:**

A minimal `ChannelPlugin` that exposes connection status to the dashboard. This follows the IRC extension pattern (`extensions/irc/src/channel.ts`).

Import `ChannelPlugin` type from `openclaw/plugin-sdk` and `getConnectionStatus` from `./status-store.js`.

Export `pipesBotChannelPlugin` as a `ChannelPlugin` with:

- `id`: `"pipes-bot-channel"`
- `meta`: `{ id: "pipes-bot-channel", label: "PipesBot (WhatsApp)", selectionLabel: "PipesBot (WhatsApp)", docsPath: "/docs/channels/pipes-bot", blurb: "WhatsApp via PipesBot managed proxy" }` — All required fields (dashboard crashes without meta).
- `capabilities`: `{ chatTypes: ["direct"], media: true }`
- `config`:
  - `listAccountIds: () => ["default"]`
  - `resolveAccount: () => ({ apiKey: "configured" })`
  - `isConfigured: () => true`
- `status`:
  - `defaultRuntime`: `{ accountId: "default", connected: false, lastError: null }`
  - `buildAccountSnapshot: ({ runtime }) => { ... }` — Reads from `getConnectionStatus()` and returns:
    ```typescript
    {
      accountId: "default",
      connected: status.connected,
      running: !status.authFailed,
      lastConnectedAt: status.lastConnectedAt,
      lastError: status.authFailed
        ? "Authentication failed -- check your pk_ API key"
        : (status.lastError ?? runtime?.lastError ?? null),
    }
    ```

**Important:** Do NOT include a `gateway` property on the channel plugin. Omitting it prevents the channel manager from trying to start/stop accounts independently of the service lifecycle.

**Update `src/service.ts`:**

1. Add import at top:
   ```typescript
   import { updateConnectionStatus } from "./status-store.js";
   import type { ConnectionState } from "./connection.js";
   ```

2. In `start()`, after creating the connection and before `connection.connect()`, add a `"state"` event listener:
   ```typescript
   connection.on("state", (state: ConnectionState) => {
     updateConnectionStatus({
       connected: state === "connected",
       ...(state === "connected"
         ? { lastConnectedAt: Date.now(), lastError: null }
         : {}),
     });
   });
   ```

   Key behavior per context decisions:
   - `connected` -> `{ connected: true, lastConnectedAt: now, lastError: null }`
   - `reconnecting` -> `{ connected: false }` (preserves lastError — do NOT clear it)
   - `disconnected` -> `{ connected: false }` (preserves lastError)

3. Update the existing `connection.on("error", ...)` handler to also update the status store:
   ```typescript
   connection.on("error", (err: Error) => {
     const isAuthFailure = err.message.includes("auth failed");
     updateConnectionStatus({
       connected: false,
       authFailed: isAuthFailure,
       lastError: err.message,
     });
     ctx.logger.error(`pipes-bot-channel: fatal connection error: ${err.message}`);
   });
   ```

   Auth failure detection: `connection.ts` line 103 emits `new Error("WebSocket auth failed: HTTP ${statusCode}")`, so matching `"auth failed"` in the message string is correct.

4. In `stop()`, reset the status store:
   ```typescript
   updateConnectionStatus({ connected: false, lastError: null });
   ```

**Update `index.ts`:**

1. Add import:
   ```typescript
   import { pipesBotChannelPlugin } from "./src/channel.js";
   ```

2. In `register()`, add `registerChannel` call BEFORE the existing `registerService` call:
   ```typescript
   register(api: OpenClawPluginApi): void {
     setPipesBotRuntime(api.runtime);
     api.registerChannel({ plugin: pipesBotChannelPlugin });
     api.registerService(createPipesBotService());
     api.logger.info("pipes-bot-channel: registered");
   },
   ```

   This follows the IRC pattern: `registerChannel` is a static declaration that does not start a connection. The `registerService` call starts the WS connection via the service lifecycle.
