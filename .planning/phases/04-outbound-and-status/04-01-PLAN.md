**In `src/types.ts`:**

Add the `PipesBotReplyStatus` type and `isPipesBotReplyStatus` type guard at the end of the file (before the PluginLogger alias):

```typescript
export type PipesBotReplyStatus = {
  type: "reply_status";
  data: {
    conversationId: string;
    success: boolean;
    messageId?: string;    // Present on success
    error?: string;        // Present on failure
    code?: string;         // Present on failure
  };
};

export function isPipesBotReplyStatus(msg: unknown): msg is PipesBotReplyStatus {
  return (
    typeof msg === "object" &&
    msg !== null &&
    "type" in msg &&
    (msg as { type: unknown }).type === "reply_status" &&
    "data" in msg
  );
}
```

The type guard follows the same pattern as the existing `isPipesBotMessage`.

**Create `src/outbound.ts`:**

This module handles reply_status correlation and failure classification. Structure:

1. **Types:** `ReplyFailureKind` union type (SERVICE_WINDOW_EXPIRED | RATE_LIMITED | FORBIDDEN | NOT_FOUND | SEND_FAILED | UNKNOWN), `PendingReply` type.

2. **Module-level state:** `pendingReplies = new Map<string, PendingReply>()` with `PENDING_TTL_MS = 30_000` (30 seconds).

3. **`trackOutboundReply(conversationId: string): void`** — Adds entry to pendingReplies map with current timestamp and expiry. On each call, performs lazy eviction: iterate map entries, delete any where `Date.now() > expiresAt`.

4. **`handleReplyStatus(msg: unknown, opts: { logger: PluginLogger; core: PluginRuntime }): void`** — The main handler:
   - Return early if `!isPipesBotReplyStatus(msg)`
   - Extract `data` from message
   - Look up and delete pending entry from `pendingReplies` by `data.conversationId`
   - **On success (`data.success === true`):**
     - Log info: `pipes-bot-channel: reply delivered to ${data.conversationId} (messageId: ${data.messageId})`
     - Return (success is log-only per context decision)
   - **On failure:**
     - Classify error via `classifyReplyFailure(data.code)` -> `ReplyFailureKind`
     - Build human-readable message via `buildFailureMessage(kind, data.error)`
     - Log error: `pipes-bot-channel: reply failed for ${data.conversationId}: [${kind}] ${data.error ?? "unknown error"}`
     - If a pending entry existed (we had context for this conversation), AND `data.conversationId` is non-empty, enqueue system event for the agent:
       ```typescript
       opts.core.system.enqueueSystemEvent(message, {
         sessionKey: `default:${data.conversationId}`,
       });
       ```

5. **`classifyReplyFailure(code?: string): ReplyFailureKind`** — Private function. Switch on `code` string to return the matching `ReplyFailureKind`. Default to `"UNKNOWN"`.

6. **`buildFailureMessage(kind: ReplyFailureKind, raw?: string): string`** — Private function.
   - For `SERVICE_WINDOW_EXPIRED`: Return `"Unable to send reply: the 24-hour WhatsApp messaging window has expired. The contact must send a new message to reopen the conversation."`
   - For all others: Return `"Reply failed: ${raw ?? kind}"`

Import `PluginLogger` from `./types.js`, `isPipesBotReplyStatus` from `./types.js`, and `PluginRuntime` from `openclaw/plugin-sdk`.

2. **Update the `connection.on("message", ...)` handler** to route `reply_status` events before inbound handling:
   ```typescript
   connection.on("message", (msg: object) => {
     // Route reply_status events to outbound handler
     if (isPipesBotReplyStatus(msg)) {
       handleReplyStatus(msg, { logger: ctx.logger, core: getPipesBotRuntime() });
       return;
     }

     // Route whatsapp_message events to inbound handler
     void handleInbound(msg, {
       apiKey,
       accountId: "default",
       send: (payload: object) => {
         const sent = connection!.send(payload);
         if (sent) {
           // Track outbound for reply_status correlation
           const replyData = (payload as { data?: { conversationId?: string } }).data;
           if (replyData?.conversationId) {
             trackOutboundReply(replyData.conversationId);
           }
         }
         return sent;
       },
       logger: ctx.logger,
     }).catch((err: unknown) => {
       ctx.logger.error(`pipes-bot-channel: inbound error: ${String(err)}`);
     });
   });
   ```

Key changes:
- The `reply_status` check happens first (early return) — only `whatsapp_message` events reach `handleInbound`
- The `send` callback is wrapped: after a successful `connection.send()`, it calls `trackOutboundReply(conversationId)` so that when the corresponding `reply_status` arrives, we can correlate it
- The `send` callback still returns the boolean result for the existing warn-on-false logic in `inbound.ts`
