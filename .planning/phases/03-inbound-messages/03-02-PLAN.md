**Signature:**
```typescript
export async function handleInbound(
  msg: unknown,
  opts: {
    apiKey: string;
    accountId: string;
    send: (payload: object) => boolean;
    logger: PluginLogger;
  },
): Promise<void>
```

**Flow (follow the research skeleton closely):**

1. Type guard: `if (!isPipesBotMessage(msg)) return;`
2. Skip unsupported: `if (data.type === "unsupported") return;`
3. Skip reaction removal (no emoji): `if (data.type === "reaction" && !data.reaction?.emoji) return;`
4. Resolve body:
   - `text`: `data.body`
   - `reaction`: `data.reaction.emoji` (already checked non-null above)
   - `location`: `""` (Body stays empty per decision)
   - `contacts`: `""` (Body stays empty)
   - All media types (image/audio/video/document/sticker): `data.body` (caption) or `""`
5. Resolve media payload — call `resolveMediaPayload()` helper:
   - For types `image`, `audio`, `video`, `document`, `sticker`: check `data.media && !data.media.unavailable && data.media.downloadUrl`, then call `downloadPipesBotMedia()`, then `buildAgentMediaPayload([{ path, contentType }])`
   - If download fails or media unavailable: log warning, return `{}` (proceed as text-only)
6. Resolve contacts payload — for type `contacts`:
   - Build VCF string from `data.contacts` array (BEGIN:VCARD/VERSION:3.0/FN/TEL/END:VCARD per contact)
   - Save via `core.channel.media.saveMediaBuffer(Buffer.from(vcard, "utf-8"), "text/vcard", "inbound")`
   - Return `buildAgentMediaPayload([{ path: saved.path, contentType: "text/vcard" }])`
7. Resolve location context — for type `location`:
   - Build `NormalizedLocation` from `data.location` (latitude, longitude, name, address)
   - Return `toLocationContext(loc)`
8. Resolve ReplyToId — for type `reaction`: `data.reaction.messageId`; otherwise `undefined`
9. Build SessionKey: `${opts.accountId}:${data.conversationId}`
10. Resolve agent route: `core.channel.routing.resolveAgentRoute({ cfg, channel: "pipes-bot-channel", accountId, peer: { kind: "direct", id: data.conversationId } })`
11. Resolve store path: `core.channel.session.resolveStorePath(cfg.session?.store, { agentId: route.agentId })`
12. Finalize inbound context: `core.channel.reply.finalizeInboundContext({...})` with ALL fields from research:
    - `Body`, `RawBody`, `CommandBody` = the resolved body/rawBody
    - `From`: `pipes-bot-channel:${data.fromNumber}`
    - `To`: `pipes-bot-channel:${data.poolNumberPhoneNumber}`
    - `SessionKey`, `AccountId`, `ChatType: "direct"`, `SenderName: data.fromName ?? undefined`, `SenderId: data.fromNumber`
    - `Provider: "pipes-bot-channel"`, `Surface: "pipes-bot-channel"`
    - `MessageSid: data.messageId`, `Timestamp: new Date(data.timestamp).getTime()`
    - `ConversationLabel: data.fromName ?? data.fromNumber`
    - `ReplyToId`, `OriginatingChannel: "pipes-bot-channel"`, `OriginatingTo: pipes-bot-channel:${data.conversationId}`
    - Spread `...mediaPayload`, `...locationCtx`
13. Record session: `core.channel.session.recordInboundSession({ storePath, sessionKey, ctx, onRecordError })`
14. Dispatch: `core.channel.reply.dispatchReplyFromConfig({ ctx, cfg, dispatcher, replyOptions: {} })`
    - `dispatcher.deliver` sends `{ type: "whatsapp_reply", data: { conversationId, poolNumberId, toNumber: data.fromNumber, text: payload.text ?? "" } }` via `opts.send()`
    - `dispatcher.onError` logs error

Update `src/service.ts`:

1. Add import: `import { handleInbound } from "./inbound.js";`
2. Replace the Phase 3 stub in `connection.on("message", ...)`:

Before:
```typescript
connection.on("message", (msg: object) => {
  void msg; // Phase 3 stub
});
```

After:
```typescript
connection.on("message", (msg: object) => {
  void handleInbound(msg, {
    apiKey,
    accountId: "default",
    send: (payload: object) => connection.send(payload),
    logger: ctx.logger,
  }).catch((err: unknown) => {
    ctx.logger.error(`pipes-bot-channel: inbound error: ${String(err)}`);
  });
});
```

Key points:
- `void handleInbound(...)` is fire-and-forget — do NOT await in the synchronous event callback (avoids blocking the WS message loop on media downloads, per research anti-pattern)
- `.catch()` ensures unhandled rejections are logged, not swallowed
- `accountId: "default"` — per research open question, v1 uses hardcoded "default" for single-account setup
- `send` delegates to `connection.send()` which returns boolean (already typed in Phase 2)
- The `connection` variable is already in closure scope from `start()`

IMPORTANT: `connection` is typed as `PipesBotConnection | null` in the outer scope. The `send` callback captures the NON-null `connection` reference that exists at the time `start()` runs. This is safe because `connection.on("message")` only fires while the connection is alive.
