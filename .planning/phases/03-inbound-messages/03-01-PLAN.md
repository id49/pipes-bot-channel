type PipesBotMessage = {
  type: "whatsapp_message";

Export a type guard `isPipesBotMessage(msg: unknown): msg is PipesBotMessage` that checks `typeof msg === "object" && msg !== null && "type" in msg && (msg as any).type === "whatsapp_message" && "data" in msg`.

<task type="auto">
  <name>Task 2: Create media download function</name>
  <files>src/media.ts</files>
  <action>
Create `src/media.ts` with:

```typescript
const PIPES_BOT_API_BASE = "https://api.pipes.bot";
```

Export `downloadPipesBotMedia(params)` where params is:
```typescript
{
  downloadUrl: string;   // relative path e.g. "/v1/media/download/xyz"
  mimeType: string;
  fileName?: string;
  apiKey: string;
  logger: PluginLogger;
}
```

Returns `Promise<{ path: string; contentType: string } | null>`.

Implementation:
1. Construct absolute URL: `${PIPES_BOT_API_BASE}${params.downloadUrl}`
2. Call `core.channel.media.fetchRemoteMedia({ url, fetchImpl, filePathHint })` where:
   - `fetchImpl` wraps fetch to inject `Authorization: Bearer ${params.apiKey}` header
   - `filePathHint` is `params.fileName` (for documents with original names)
3. Call `core.channel.media.saveMediaBuffer(fetched.buffer, fetched.contentType ?? params.mimeType, "inbound")`
4. Return `{ path: saved.path, contentType: saved.contentType ?? params.mimeType }`
5. On error: log with `logger.error(...)`, return `null`

Import `getPipesBotRuntime` from `"./runtime.js"` and `PluginLogger` from `"./types.js"`.

IMPORTANT: The `fetchImpl` override is required because `fetchRemoteMedia` doesn't add auth headers automatically. The PipesBot download endpoint returns 302 to a presigned R2 URL — `fetchRemoteMedia` follows redirects automatically.
  </action>
  <verify>Run `npx tsc --noEmit` — should pass with zero errors.</verify>
  <done>media.ts exports downloadPipesBotMedia. It constructs absolute URL from relative downloadUrl, injects auth header, calls fetchRemoteMedia + saveMediaBuffer, returns path + contentType or null on failure. Type check passes.</done>
