  <action>
Create `src/connection.ts` implementing the `PipesBotConnection` class. Follow the research skeleton closely (02-RESEARCH.md "Full Connection Class Skeleton") with these specifics:

**Exports:**
- `type ConnectionState = "connected" | "disconnected" | "reconnecting"`
- `class PipesBotConnection extends EventEmitter`

**Constructor:** Takes `apiKey: string` and `logger: PluginLogger` (from `openclaw/plugin-sdk`).

**Public API:**
- `connect(): void` -- sets `shouldReconnect = true`, calls `doConnect()`
- `disconnect(): void` -- teardown in exact order: (1) set `shouldReconnect = false`, (2) `stopHeartbeat()`, (3) clear `reconnectTimer`, (4) `ws.close(1000)`, (5) null `ws`, (6) `setState("disconnected")`
- `send(message: object): boolean` -- returns false if not connected
- `getState(): ConnectionState` -- synchronous accessor

**Private methods:**
- `doConnect()` -- creates `new WebSocket(buildWsUrl(apiKey), { handshakeTimeout: 10_000 })` and registers all listeners:
  - `unexpected-response`: check `response.statusCode` -- 401/403 = permanent failure (set `shouldReconnect = false`, emit `"error"`), anything else = transient (schedule reconnect)
  - `open`: reset `reconnectAttempts = 0`, `setState("connected")`, `startHeartbeat(ws)`, log info
  - `message`: `JSON.parse(data.toString())`, emit `"message"` event. Catch parse errors and log warn.
  - `error`: log only (close fires next, handles reconnect)
  - `close`: `stopHeartbeat()`, null `ws`, check `shouldReconnect` -- if true: `scheduleReconnect()`, else: `setState("disconnected")`

- `scheduleReconnect()` -- `setState("reconnecting")`, increment `reconnectAttempts`, compute delay with `computeBackoffDelay()`, log attempt number and delay, set `reconnectTimer` to call `doConnect()` after delay

- `setState(next)` -- no-op if `state === next`, otherwise update `state`, emit `"state"` event, log state changes (connected/disconnected at info level; reconnecting is logged in scheduleReconnect)

- `startHeartbeat(ws)` -- 25s `setInterval` sending `ws.ping()`, each ping starts a 50s `setTimeout` (pong deadline). `ws.on("pong")` clears the pong timer. If pong deadline fires, log error and `ws.terminate()`.

- `stopHeartbeat()` -- clear both `pingTimer` and `pongTimer`

**Module-level helpers (not exported):**
- `computeBackoffDelay(attempt: number): number` -- full jitter: `Math.floor(Math.random() * Math.min(120_000, 1_000 * Math.pow(2, attempt)))`
- `buildWsUrl(apiKey: string): string` -- `wss://api.pipes.bot/ws?apiKey=${encodeURIComponent(apiKey)}`

**Constants:**
- `BASE_MS = 1_000`
- `MAX_MS = 120_000` (2 min -- user decision)
- `PING_INTERVAL_MS = 25_000`
- `PONG_TIMEOUT_MS = 50_000` (75s total with ping interval = WS-03)

**Import style:** Use `import WebSocket from "ws"` and `import { EventEmitter } from "node:events"`. Use `.js` extension on NO imports (these are all package imports, not relative).

**Critical patterns from research (do not deviate):**
- Only schedule reconnect in `close` handler (never in `error` handler) to prevent double scheduling
- Reset `reconnectAttempts` in `open` handler
- Set `shouldReconnect = false` BEFORE `ws.close()` in disconnect
- Never log the WebSocket URL (contains API key)
- `ws.terminate()` (not `ws.close()`) on pong timeout -- forces code 1006
