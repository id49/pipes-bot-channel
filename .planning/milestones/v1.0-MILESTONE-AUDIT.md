## Tech Debt

### Phase 4: Outbound and Status

**1. BUG — authFailed not reset on stop()**
- **File:** `src/service.ts` line 84
- **Issue:** `stop()` calls `updateConnectionStatus({ connected: false, lastError: null })` but does not include `authFailed: false`
- **Impact:** After correcting an invalid API key and restarting, dashboard permanently shows `running: false` because `authFailed` stays `true` in module-level store
- **Fix:** Change to `updateConnectionStatus({ connected: false, authFailed: false, lastError: null })`

**2. MINOR — pongTimer overwrite without clearing**
- **File:** `src/connection.ts` line 174
- **Issue:** `this.pongTimer = setTimeout(...)` overwrites previous reference without clearing
- **Impact:** Theoretical timer leak if PING_INTERVAL and PONG_TIMEOUT overlap (cannot happen with current 25s/50s constants)
- **Fix:** Add `if (this.pongTimer !== null) { clearTimeout(this.pongTimer); }` before the assignment

**3. OBSERVATION — pendingReplies not cleared on stop**
- **File:** `src/outbound.ts` (module-level Map)
- **Issue:** Module-level `pendingReplies` Map persists across service restart cycles
- **Impact:** A `reply_status` arriving within 30s of restart could match a pre-restart entry (low probability, 30s TTL eviction covers most cases)
- **By design:** Decision D-04-01-B chose lazy eviction over timer-based cleanup

### Total: 3 items across 1 phase
